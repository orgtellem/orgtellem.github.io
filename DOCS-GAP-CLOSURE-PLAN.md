# Tellem Documentation Gap Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Закрыть оставшиеся пользовательские пробелы публичной документации Tellem и сделать логотип сайта заметнее на desktop и mobile.

**Architecture:** Документация строится вокруг задач владельца бизнеса, а не внутренней структуры Java-модулей. Каждая новая страница отвечает за один рабочий сценарий, опирается на актуальные подписи и ограничения из кода CRM/клиентского приложения и связывается с соседними страницами. Скриншоты не используются; Telegram остаётся опциональной интеграцией.

**Tech Stack:** MkDocs Material, Markdown, `mkdocs-static-i18n`, `mkdocs-redirects`, custom CSS.

**Spec:** Этот файл, раздел «Общие ограничения и решения».

## Общие ограничения и решения

- Источник истины для поведения продукта — актуальный код `frd_crm`, XML-дескрипторы и message bundles; старые тексты используются только после повторной проверки.
- Основной термин — «клиентское приложение»; Telegram описывается только как дополнительный канал.
- Скриншоты интерфейса и ссылки на них не добавляются.
- Названия меню записываются полным путём: «Раздел → Пункт».
- Публичная документация не описывает Entity Inspector, JMX, Quartz, блокировки и другие технические экраны Jmix.
- Новые страницы добавляются в `mkdocs.yml`; удаление или переименование существующих адресов допускается только с redirect.
- Русский остаётся основным языком; структура совместима с будущими файлами `*.en.md`.
- Перед завершением обязательны `mkdocs build --strict`, проверки терминологии/ссылок и браузерная проверка desktop/mobile.
- Коммиты и push выполняются только после отдельного явного запроса пользователя.
