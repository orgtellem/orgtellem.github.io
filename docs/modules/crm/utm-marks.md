# Метки и пригласительные ссылки { #tags-and-invitation-links }

Создайте отдельные ссылки для рекламы или партнёров, чтобы сравнить пришедших клиентов.

Где: **Маркетинг → Метки** для создания и **Аналитика → Источники** для статистики.

<span id="_2"></span>

## Создать метку { #create-a-tag }

1. Выберите «Метка» над таблицей и нажмите «Создать».
2. Укажите наименование и тип. Для «Пользовательская» задайте уникальный код до 30 символов. Для «UTM-формат» заполните источник, тип трафика и название кампании, до 20 символов каждое. UTM означает стандартные параметры ссылки, которые обозначают источник перехода и кампанию.
3. Используйте латинские буквы, цифры и дефис. Набор трёх UTM-значений должен быть уникальным.
4. При необходимости выберите группу и сохраните.

Группа объединяет метки в статистике и не имеет своей ссылки. Например, создайте группу «Блогеры (октябрь)» и метку для каждого блогера.

<span id="_3"></span>

## Получить ссылку { #get-the-link }

Нажмите «Скопировать ссылку» в списке или используйте «Пригласительная ссылка» в карточке:

| Тип | Формат ссылки |
| --- | --- |
| Пользовательская | `<адрес приложения>/?start=<код>` |
| UTM | `<адрес приложения>/?start=<источник>_<тип трафика>_<кампания>` |

Для Telegram возьмите то же значение после `start=`:

- `https://t.me/<бот>/app?startapp=m-<значение>` открывает Mini App с коротким именем `app`; сначала [настройте Mini App](../../getting-started/bot-setup.md#4-mini-app). Метка привязывается при входе покупателя.
- `https://t.me/<бот>?start=<значение>` открывает чат; метка привязывается только новому пользователю бота.

В браузере также можно использовать `utm_source`, `utm_medium`, `utm_campaign`: они учитываются для UTM-метки с совпадающими значениями.

## Проверить статистику { #statistics }

В **Аналитика → Источники** выберите группу и период. Пустой фильтр группы покажет только метки без группы. Даты ограничивают время привязки метки, а не регистрации аккаунта; границы дней зависят от часового пояса пользователя CRM.

### Эффективность меток { #effectiveness }

В таблице **«Эффективность меток»** сравните покупки клиентов по их первой известной метке за всю историю. При смене группы или периода более поздняя метка не заменяет первую. Клиенты, которые покупали до привязки метки, показаны отдельно и не входят в показатели привлечения. «Без покупок до метки» может включать давно зарегистрированных клиентов.

| Показатель | Как читать |
| --- | --- |
| Первый заказ за 30 дней | Доля клиентов с первой завершённой покупкой в течение 30 дней после метки |
| Повтор за 30 дней / Повтор за 60 дней | Доля первых покупателей со вторым завершённым заказом в течение 30 или 60 дней после первого |
| Выручка за 30 дней на клиента | Выручка за 30 дней после метки, делённая на число клиентов в расчёте, включая не купивших |

Для каждого показателя учитываются клиенты, у которых прошло полное окно наблюдения: для первого заказа и выручки от метки, для повтора от первой покупки. Поэтому число клиентов в расчёте различается. Поздний первый заказ может участвовать в повторных покупках, даже если не попал в «Первый заказ за 30 дней».

Учитываются завершённые заказы всех точек сети; выручка следует [общим правилам аналитики](analytics.md#filters-and-calculations). Для долей при базе меньше 30 клиентов вместо процентов видны абсолютные числа: например, «10 / 20» означает, что купили 10 из 20 клиентов. При отсутствии данных для расчёта виден «—». Нажмите **«Скачать CSV»**, чтобы выгрузить текущую таблицу вместе с числом клиентов в каждом расчёте.

### Привязки меток на графиках { #tag-links }

Графики под таблицей показывают все привязки меток, включая существующих клиентов. Клиент считается один раз на метку и может попасть в несколько меток, поэтому числа отличаются от таблицы эффективности. В браузере метка привязывается после перехода по ссылке и входа в приложение как нового, так и существующего клиента.

Эти данные не показывают число кликов или расходы на рекламу и не доказывают, что именно ссылка привела к покупке.
