# Уведомления

Кто и о чём узнаёт: сотрудники — о заказах и остатках, покупатели — о смене статуса заказа.

Где: **Настройки → Уведомления**. Справа два списка: «Уведомления для продавцов» и «Уведомления для клиентов». Выбранное уведомление открывается слева.

## Для продавцов

| Уведомление | Когда приходит |
|---|---|
| «Низкое количество товара» | Остаток позиции изменился и стал меньше значения «Если менее» (по умолчанию 5). Архивные товары не учитываются. |
| «Уведомление о новом заказе» | Заказ создан в статусе «Новый» или «Ожидает оплаты», то есть ещё до оплаты. |
| «Уведомление об отмененном заказе» | Заказ стал «Отменён» — при отмене покупателем и из CRM. |
| «Уведомление о просроченной оплате» | Заказ из «Ожидает оплаты» стал «Ошибка оплаты» (вышло «Время ожидания платежа» или платёж отклонён) либо отменён до оплаты. |
| «Напоминание о непросмотренных заказах» | Каждые N минут, пока есть заказы в статусе «Новый». N — по умолчанию 20; поле подписано «Если менее». |

«Время ожидания платежа» задаётся в способе оплаты ([«Оплата»](payment-providers.md)).

## Получатели

Таблица «Получатели уведомления»: «Добавить» выбирает клиента из списка, «Удалить» убирает. Подойдёт любой аккаунт покупателя, не обязательно с Telegram. Поля сохраняются сразу.

- «Телеграм» и «Эл. почта» — независимые каналы; по умолчанию включён только «Телеграм». Для «Эл. почта» заполните «Адрес Эл. Почты»; на платформе должна быть настроена отправка почты.
- «Магазины» — магазины и сети из «Каталог → Магазины», по заказам которых приходят уведомления. Поле обязательно: без него уведомление не придёт. У «Низкое количество товара» такой колонки нет.
- Для канала «Телеграм» нужны клиент с привязанным Telegram и включённая [«Интеграции → Telegram»](../../getting-started/bot-setup.md). Переключатель рядом с названием уведомления выключает только Telegram, письма продолжают приходить.

## Для клиентов

«Изменение статуса заказа»: покупатель получает сообщение о каждой смене статуса: push (если разрешил), Telegram (если связан с ботом магазина) и e-mail (если адрес подтверждён и на платформе настроена отправка почты); статусы называются так же, как в CRM и приложении. К системному тексту можно добавить свой для конкретного статуса: «Создать» → «Статус» и «Сообщение»; «Итоговое сообщение» — предпросмотр. На статус — одно сообщение, чтобы изменить текст, правьте существующее.

- Сообщение добавляется в Telegram и e-mail, в push его нет. Уходит основной текст; переводы в уведомлении не используются.
- Маска `%name%`, где name — имя системного атрибута заказа, подставляет его значение. Атрибуты записывают [пользовательские интеграции](integrations.md).
