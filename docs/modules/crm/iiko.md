# Интеграция с Айко

Интеграция связывает точки продаж и товары Tellem с организациями, терминалами и номенклатурой Айко. Для подключения нужны API-ключ (`apiKey`) из iikoWeb и учётные данные приложения (`appId`, `clientSecret`) с портала разработчика iiko.

## Создание конфигурации

Откройте «Интеграции → iiko», нажмите «Добавить интеграцию» и пройдите четыре шага.

Каждая конфигурация показана отдельной карточкой: названия заведений, количество терминалов
и настроек оплаты, количество позиций в загруженных стоп-листах, режим обновления и последняя успешная синхронизация.
«Настроить» открывает конфигурацию. Удаление требует подтверждения.

1. «Учётные данные API» — укажите понятное название конфигурации, «API-ключ», «App ID» и «Client secret». CRM проверит доступ к Айко перед переходом дальше.
2. «Терминалы iiko» — для каждой точки продаж выберите организацию и терминальную группу. Заказы этой точки будут отправляться на выбранный терминал.
3. «Настройки способов оплаты» — сопоставьте способы онлайн-оплаты Tellem с типами оплаты Айко и укажите, обрабатывается и фискализируется ли платёж внешней системой.
4. «Стоп-лист iiko» — после сохранения конфигурации здесь доступны состояние подписки и остановленные товары. Нажмите «OK», чтобы сохранить конфигурацию и завершить настройку.

«Далее» проверяет обязательные поля текущего шага. Сохранение проверяет также предыдущие шаги:
при пропущенном поле экран вернётся к нужной вкладке и подскажет, что заполнить.

Если проверка учётных данных или загрузка справочников не проходит, не сохраняйте незавершённую конфигурацию: проверьте доступ ключа к организациям и терминалам в Айко.

Для проверки на тестовом контуре подготовьте опубликованное меню с ценами, активную терминальную группу iikoFront, столы, типы заказов для зала и самовывоза и хотя бы один активный тип оплаты.

## История операций

В разделе «Интеграции → iiko» нажмите **«История операций»** рядом с кнопкой «Добавить интеграцию».
Таблица показывает фактические вызовы API встроенной интеграции iiko, входящие callback и результаты обновления стоп-листов.
В заголовках столбцов доступны фильтры по времени, типу, операции, результату, конфигурации, заведениям, инициатору и HTTP-статусу.
«Обновить» загружает новые записи; «Подробности» открывает выбранную операцию только для чтения.

Для стоп-листов видны инициатор обновления и товары, добавленные в список или снятые с него.
«Успешно» у вызова API означает, что iiko ответил без HTTP-ошибки (итог операции зависит от содержимого ответа), а у callback — что событие принято.
Результат применения стоп-листа показан отдельно. Ошибки содержат HTTP-статус или безопасное описание причины.

Надпись «Стоп-листы обновляются через callback от iiko» в карточке подтверждает настройку подписки в Айко, но не доставку событий.
Чтобы проверить доставку, выберите в фильтре столбца «Тип» значение «Колбэк» и нажмите «Обновить» после изменения стоп-листа в iikoFront.
История показывает также отклонённые запросы. После принятого `StopListUpdate` ищите обновление стоп-листа
с инициатором «Вебхук iiko».

При HTTP 401 откройте «Подробности»: причина покажет, отсутствует ли заголовок авторизации,
неверен ли его формат или токен не совпадает с настройками callback CRM. Сам токен в историю не записывается.
После обновления CRM подписка callback проверяется автоматически; пересоздавать конфигурацию не требуется.

История сохраняет названия конфигурации и заведений на момент операции и остаётся после удаления конфигурации.
Ключи, токены и полные тела запросов и ответов в историю не записываются.

## Сопоставление товаров

В iiko отправляются только товары, созданные как «Товар Iiko». Откройте «Каталог → Товары», нажмите «Создать» → «Товар Iiko» и в поле «Товар из IIKO» выберите позицию меню iiko: название, цена и артикул подставятся из iiko. Пункт появляется, когда сохранена хотя бы одна конфигурация iiko. Каждую позицию iiko можно связать только с одним товаром; связь задаётся при создании товара.

Обычные товары в iiko не передаются: заказ с ними не будет отправлен. Экран «Конфигурирование товаров» (кнопка «Товары» в карточке конфигурации) на отправку заказов и стоп-листы не влияет.

## Отправка заказов

### QR-коды для столов

1. Подключите для точки способ получения «В заведении».
2. Сохраните конфигурацию iiko с привязкой точки. CRM автоматически создаст
   необязательное текстовое поле «Стол» для всех способов «В заведении»,
   включая способы, добавленные позже. Повторная настройка не создаёт дублей.
3. В «Каталог → Магазины» нажмите «Распечатать QR-код» и выберите заведение.
   Выделенная в списке точка будет выбрана заранее. При настроенной интеграции iiko
   появятся залы со столами.
4. Нажмите на стол на плане зала. Если в iiko не настроен
   план, показаны карточки столов по номерам. Нажмите «Распечатать QR-код».
   На листе будут QR, название точки и номер стола. Разместите его на этом столе.

Если привязка стола ещё не настроена, в окне QR появится кнопка «Настроить столы».
Она создаст недостающие поля для выбранного заведения одним нажатием.
Существующие поля с ключом интеграции `iikoTable` сохраняются.

После сканирования клиент выберет нужную точку и запомнит стол для следующего
заказа «В заведении». Номер автоматически заполняет видимое поле стола.
Покупатель может изменить номер или очистить поле перед оформлением.
Если номер сохранён из QR, iiko получает точный стол по его идентификатору;
при изменении используется введённый номер.
Стол очищается после успешного заказа, смены точки или способа получения;
через два часа требуется повторное сканирование.

Список и план запрашиваются при выборе заведения. «Обновить столы» повторяет запрос,
в том числе после ошибки iiko. Общий QR остаётся доступен: нажмите «QR для всего
заведения». При смене заведения выбранный стол сбрасывается.
Если столов нет, проверьте привязку точки на шаге «Терминалы iiko» и публикацию
залов и столов выбранного терминала в iiko, затем нажмите «Обновить столы».
Столы других терминалов не подставляются.
Старое числовое поле `iikoTable` поддерживается, но при одинаковых номерах столов
в разных залах используйте текстовое поле.

### Настройка отправки

После сохранения конфигурации iiko заказы отправляются автоматически, в том числе
для ранее настроенных конфигураций. Создавать дополнительную пользовательскую
интеграцию для отправки в iiko не требуется.

При оплате наличными или картой при получении, а также способом «Перевод онлайн»
заказ передаётся в iiko в статусе «Новый» без платежа: сопоставление способа оплаты
не требуется. Заказ закрывает кассир в iikoFront (при оплате при получении он же
принимает оплату), CRM отслеживает его статус без повторных команд закрытия.

При онлайн-оплате по ссылке заказ передаётся после перехода в «Оплачено» и закрывается
автоматически. Сопоставление способа оплаты обязательно и настраивается на шаге
«Настройки способов оплаты».

Проведите тест на отдельном заказе и проверьте:

- правильную точку и терминал;
- что все товары заказа созданы как «Товар Iiko»;
- тип оплаты и фискализацию;
- дальнейшее изменение статуса заказа.

Если заказ не появился в iikoFront, передайте сотруднику поддержки номер заказа.
В журналах CRM записаны начало отправки, полученный идентификатор iiko и ошибки.
Сообщения об ошибках на русском содержат причину и подсказку, что проверить.
Если iiko не вернул столы, проверьте привязку точки на шаге «Терминалы iiko»
и настройку залов и столов именно этого терминала. Если номер не найден или
повторяется, проверьте номер либо используйте QR-код конкретного стола.
Для ошибок онлайн-оплаты, авторизации и сети журнал указывает нужную настройку.
Ошибка «Товар … не сопоставлен с товаром iiko» означает, что в заказе есть обычный товар:
в iiko передаются только товары, созданные как «Товар Iiko» (см. «Сопоставление товаров»).
Экран «Конфигурирование товаров», на который ссылается сообщение, на отправку заказов не влияет.

Статусы обновляются через webhook и резервный опрос iiko каждые пять минут для
заказов без обновлений более трёх минут. Закрытый заказ становится «Завершён»,
отменённый — «Отменён». Повторное завершение не начисляет бонусы повторно.
Причину каждой смены статуса поддержка Tellem видит в журнале CRM. Сотрудник,
закрывший заказ в iiko, через API не передаётся.

Если iiko сообщает об ошибке заказа, CRM переводит заказ в «Ожидает обработки»
(если у заведения один открытый склад — сразу в «Собирается») и отправляет уведомление
в Telegram контактам из «Настройки → Поддержка», у которых привязан Telegram.
В уведомлении: заведение, контакты покупателя, состав и сумма заказа.

### Стоп-листы iiko

CRM скрывает блюда с нулевым или отрицательным остатком iiko в меню привязанного
заведения. Это действует также при показе товаров без остатка. Стоп товара iiko скрывает
связанный с ним товар Tellem. Если две точки
направляют заказы в один терминал, его стоп действует в обеих; другие терминалы
проверяются независимо. Стоп одного размера пока скрывает весь связанный товар.

После снятия стопа товар возвращается с текущей доступностью CRM. Ручное отключение,
складское количество и резервы сохраняются: их изменения во время стопа учитываются
при возврате. Остаток iiko не копируется на склад Tellem.

Обновление запускается при настройке интеграции, после запуска CRM и по webhook
`StopListUpdate`. Резервный опрос раз в час восстанавливает пропущенные изменения.
Для webhook нужен публичный HTTPS-адрес CRM. Существующий чужой адрес автоматически
не заменяется; при неподключённом webhook продолжает работать резервный опрос.
При ошибке API или неполном ответе сохраняется последний успешно загруженный список.
Меню обновляется при возвращении в приложение, повторном открытии и смене заведения.
Мгновенное обновление уже открытого меню не предусмотрено.

Положительный остаток iiko оставляет товар в меню, но ограничивает количество
при оформлении. Перед созданием заказа и платёжной ссылки CRM проверяет корзину
в iiko: полный стоп, превышение остатка или недоступный API останавливают оформление
с сообщением покупателю. Уже добавленный товар не удаляется из корзины молча.

Чтобы открыть шаг «Стоп-лист iiko» у сохранённой конфигурации, нажмите в карточке «Настроить»
и пройдите предыдущие шаги кнопкой «Далее»: на первом шаге CRM заново проверит доступ к iiko.
Там показаны названия организаций и терминалов,
таблица остановленных товаров с остатком, время успешного обновления и режим автоматического
обновления: мгновенно через callback от iiko или автоматически раз в час. Ошибки настройки
callback и загрузки списка показаны отдельно от режима обновления. Товары без сопоставления
отмечены как неимпортированные. «Обновить сейчас» ставит
задачу в очередь; чтобы увидеть результат, откройте конфигурацию повторно.

Причину каждого обновления видно в «Истории операций» в столбце «Инициатор»: «Вебхук iiko»,
«Часовой опрос», «Настройка интеграции», «Запуск CRM» или «Администратор» (кнопка «Обновить сейчас»).

!!! warning
    Не меняйте служебный webhook-токен без команды Tellem. Его редактирование доступно только администратору платформы и не относится к обычной настройке магазина.
