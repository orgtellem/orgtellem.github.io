# Интеграция с Айко

Интеграция связывает точки продаж и товары Tellem с организациями, терминалами и номенклатурой Айко. Для подключения нужны API-ключ (`apiKey`) из iikoWeb и учётные данные приложения (`appId`, `clientSecret`) с портала разработчика iiko.

## Создание конфигурации

Откройте «Интеграции → Айко», нажмите «Создать» и пройдите три шага.

1. «Учётные данные API» — укажите понятное название конфигурации, «API-ключ», «App ID» и «Client secret». CRM проверит доступ к Айко перед переходом дальше.
2. «Терминалы iiko» — для каждой точки продаж выберите организацию и терминальную группу. Заказы этой точки будут отправляться на выбранный терминал.
3. «Настройки способов оплаты» — сопоставьте способы онлайн-оплаты Tellem с типами оплаты Айко и укажите, обрабатывается и фискализируется ли платёж внешней системой.

Если проверка учётных данных или загрузка справочников не проходит, не сохраняйте незавершённую конфигурацию: проверьте доступ ключа к организациям и терминалам в Айко.

Для проверки на тестовом контуре подготовьте опубликованное меню с ценами, активную терминальную группу iikoFront, столы, типы заказов для зала и самовывоза и хотя бы один активный тип оплаты.

## Сопоставление товаров

Выберите созданную конфигурацию и откройте «Конфигурирование товаров». Для каждого опубликованного варианта товара Tellem выберите соответствующую позицию Айко.

Сохранение недоступно, пока у какого-либо опубликованного варианта нет соответствия. После добавления нового товара вернитесь к этому экрану и настройте его перед отправкой заказов.

## Отправка заказов

### QR-коды для столов

1. Подключите для точки способ получения «В заведении».
2. Сохраните конфигурацию iiko с привязкой точки. CRM автоматически создаст
   необязательное текстовое поле «Стол» для всех способов «В заведении»,
   включая способы, добавленные позже. Повторная настройка не создаёт дублей.
3. В «Каталог → Магазины» нажмите «Распечатать QR-код» и выберите заведение.
   Выделенная в списке точка будет выбрана заранее. При настроенной интеграции iiko
   появятся залы со столами.
4. Нажмите на стол на плане зала. Если в iiko не настроен
   план, показаны карточки столов по номерам. Нажмите «Распечатать QR-код».
   На листе будут QR, название точки и номер стола. Разместите его на этом столе.

Если привязка стола ещё не настроена, в окне QR появится кнопка «Настроить столы».
Она создаст недостающие поля для выбранного заведения одним нажатием.
Существующие поля с ключом интеграции `iikoTable` сохраняются.

После сканирования клиент выберет нужную точку и запомнит стол для следующего
заказа «В заведении». Номер автоматически заполняет видимое поле стола.
Покупатель может изменить номер или очистить поле перед оформлением.
Если номер сохранён из QR, iiko получает точный стол по его идентификатору;
при изменении используется введённый номер.
Стол очищается после успешного заказа, смены точки или способа получения;
через два часа требуется повторное сканирование.

Список и план запрашиваются при выборе заведения. «Обновить столы» повторяет запрос,
в том числе после ошибки iiko. Общий QR остаётся доступен: нажмите «QR для всего
заведения». При смене заведения выбранный стол сбрасывается.
Если столов нет, проверьте привязку точки на шаге «Терминалы iiko» и публикацию
залов и столов выбранного терминала в iiko, затем нажмите «Обновить столы».
Столы другого ресторана автоматически не подставляются. Пустой ответ записывается
в журнал ошибок CRM с заведением, организацией и терминалом.
Старое числовое поле `iikoTable` поддерживается, но при одинаковых номерах столов
в разных залах используйте текстовое поле.

### Настройка отправки

После сохранения конфигурации iiko заказы отправляются автоматически: при оплате
при получении — в статусе «Новый», при онлайн-оплате — после перехода в «Оплачено».
Для ранее настроенных конфигураций это тоже работает. Создавать дополнительную
пользовательскую интеграцию для отправки в iiko не требуется.

При оплате наличными или картой при получении заказ передаётся без платежа:
сопоставление способа оплаты с iiko не требуется. Для онлайн-оплаты по ссылке
сопоставление обязательно и настраивается на шаге «Настройки способов оплаты».

Проведите тест на отдельном заказе и проверьте:

- правильную точку и терминал;
- соответствие всех товарных вариантов;
- тип оплаты и фискализацию;
- дальнейшее изменение статуса заказа.

Если заказ не появился в iikoFront, передайте сотруднику поддержки номер заказа.
В журналах CRM записаны начало отправки, полученный идентификатор iiko и ошибки.
Сообщения об ошибках на русском содержат причину и подсказку, что проверить.
Если iiko не вернул столы, проверьте привязку точки на шаге «Терминалы iiko»
и настройку залов и столов именно этого терминала. Если номер не найден или
повторяется, проверьте номер либо используйте QR-код конкретного стола.
Для ошибок товаров, онлайн-оплаты, авторизации и сети журнал указывает нужную настройку.

Статусы обновляются через webhook и резервный опрос iiko каждые пять минут для
заказов без обновлений более трёх минут. Закрытый заказ становится «Завершён»,
отменённый — «Отменён». Повторное завершение не начисляет бонусы повторно.
В журнале смены статуса указаны предыдущий и итоговый статус, источник обновления,
пользователь CRM и причина. Сотрудник, закрывший заказ в iiko, через API не передаётся.
Обычный успешный опрос не записывает полный заказ. При ошибке сохраняются полные
данные iiko, а поддержка получает заведение, контакты покупателя, состав и сумму заказа.

!!! warning
    Не меняйте служебный webhook-токен без команды Tellem. Его редактирование доступно только администратору платформы и не относится к обычной настройке магазина.
