# Оплата

Способы оплаты, которые выбирает покупатель: онлайн-провайдеры, «Картой при получении» и «Наличными при получении».

Где: **Настройки → Оплата** (экран «Варианты оплаты»).

## Создание способа

1. «Новый сервис» → провайдер из списка.
2. Вкладка «Основное» (у Робокассы — «Данные из личного кабинета»):
    - «Наименование» видно покупателю, среди способов оплаты оно уникально;
    - «Комиссия в %» — целое от 0 до 100, по умолчанию 0. Наценка только на товары, доставка без неё. У Альфа банка и СБП (Альфа банк) поля нет;
    - «Время ожидания платежа (в минутах)» — от 1 до 60, пусто — без срока. Неоплаченный заказ становится «Ошибка оплаты»: переход делает проверка раз в минуту с запасом около 5 минут, поэтому реально он позже;
    - реквизиты провайдера — в таблице ниже.
3. Вкладка «Поля заказа»: для «Имя», «Фамилия», «Телефон» и «Почта» переключатели «Виден» и «Обязателен». Почта обязательна всегда у Т-Банка и СБП (Т-Банк), у Точка Банк — при включённой фискализации.
4. «Сохранить». У нового сервиса откроется «Смена активного сервиса»: «Сохранить активным» включает способ во всех сетях и выключает другие сервисы того же типа, «Сохранить неактивным» добавляет его выключенным. При редактировании диалога нет.

Включают способ в карточке сети: **Каталог → Магазины** → «Управление способами оплаты» ([«Магазины»](stores-and-delivery.md)).

«Картой при получении» и «Наличными при получении» есть всегда: их можно править, но не удалить. Способ, указанный в заказах, тоже не удалить.

!!! warning "Перевод онлайн"
    В «Новый сервис» его нет: приложение не показывает покупателю реквизиты, поэтому оплатить переводом он не сможет. Созданный ранее способ выключите в сетях (**Каталог → Магазины** → «Управление способами оплаты»). Заказ, уже оформленный с ним, создан «Новый»: договоритесь об оплате с покупателем и нажмите «Принять заказ» ([«Заказы»](orders.md)).

## Проверка

У онлайн-провайдеров на первой вкладке есть «Сгенерировать тестовую ссылку для оплаты»: она запрашивает ссылку у провайдера по введённым реквизитам. Если ссылка создалась и страница оплаты открывается, реквизиты приняты. Заказа у тестовой ссылки нет, поэтому статус в CRM она не меняет. Возврат в приложение и смену статуса проверьте первым настоящим заказом на небольшую сумму. До этого не включайте способ для всех сетей.

## Реквизиты

| Сервис | Поля |
|---|---|
| Т-Банк, СБП (Т-Банк) | «Идентификатор терминала», «Пароль», «Система налогообложения», «Ставка НДС», необязательный префикс номера заказа (латинские буквы, до 12) |
| Робокасса | «ID магазина», «Пароль 1», «Пароль 2», «Хэш-алгоритм» (только MD5) |
| СБП (Аркопэй) | «Логин», «Пароль», «Секретный ключ», «Предмет расчета», «НДС», «Тип ссылки СБП» (одноразовая или многоразовая) |
| Альфа банк, СБП (Альфа банк) | «Тип авторизации» («Логин и пароль» или «Токен»), необязательный префикс (латиница, до 12). «Платежи с фискализацией» открывает налоговые поля чека |
| Сбербанк, СБП (Сбербанк) | «Логин», «Пароль», «Тестовый режим», «Тип контрольной суммы уведомлений», «Ключ проверки уведомлений» |
| ЮKassa | «Идентификатор магазина», «Секретный ключ», «Формировать чек» (открывает «НДС») |
| Бета трансфер | «Публичный ключ», «Секретный ключ», «Минимальная сумма платежа» |
| Точка Банк, Точка Банк (СБП) | см. ниже |

## Уведомления провайдера

Если CRM показывает адрес для уведомлений, скопируйте его без изменений в кабинет провайдера.

- ЮKassa: вкладка «Данные для личного кабинета» — «URL для уведомлений»; события в кабинете — `payment.succeeded` и `payment.canceled`. Переключатель «Обновлять состояние платежей через планировщик» на проверку не влияет: статус ЮKassa CRM запрашивает раз в минуту всегда.
- Робокасса: та же вкладка — Result URL (POST), Success URL (GET), Fail URL (GET).
- Бета трансфер: Result, Success и Fail URL и «Api адрес» — в свёрнутом блоке «Дополнительная информация», только для чтения.
- Т-Банк и АркоПэй передают адрес в каждом платеже, настраивать нечего. Альфа банк уведомлений не использует: статус запрашивается раз в минуту.
- Сбербанк: адрес уведомлений запросите у команды Tellem и укажите в кабинете Сбербанка. Пока в CRM не заданы «Тип контрольной суммы уведомлений» и «Ключ проверки уведомлений», уведомления отклоняются, а статус подхватит проверка раз в минуту.

??? note "Точка Банк и Точка Банк (СБП)"
    - **Токен.** В кабинете Точки: «Сервисы» → «Все сервисы» → «Интеграции и API» → «JWT-ключи». Права для карты: `ReadCustomerData`, `MakeAcquiringOperation`, `ReadAcquiringData`, `ManageWebhookData`; для СБП: `ReadCustomerData`, `ReadSBPData`, `EditSBPData`, `ManageWebhookData`. В «Токен доступа» вставьте сам JWT без слова `Bearer`; `client_id` и логин конструктора сайтов не подходят.
    - **Реквизиты** CRM подгружает после ввода токена: у карты «Клиент» (компания) и «Идентификатор торговой точки», у СБП «Идентификатор торговой точки» и «Счёт». Если списки пусты, проверьте срок и права токена, режим и подключён ли продукт в банке.
    - **Webhook.** «Публичный JWK для webhook» — публичный ключ банка, не секрет: кнопка «Получить» или [источник JWK](https://enter.tochka.com/doc/openapi/static/keys/public). «URL webhook-уведомления» скопируйте в настройки интеграции Точки; события: `acquiringInternetPayment` для карты, `incomingSbpPayment` для СБП.
    - **«С фискализацией»** (только у карты). Сначала подключите услугу в интернет-банке. Почта покупателя становится обязательной: на неё уходит чек. В чек входят товары с комиссией и доставка, списанные бонусы уменьшают суммы. Действует на новые ссылки; в тестовой ссылке почта `test@example.com`.
    - **«Тестовый режим».** Введите тестовый токен `sandbox.jwt.token` из документации Точки. Для боевых платежей выключите режим, вставьте боевой токен и заново выберите реквизиты.
