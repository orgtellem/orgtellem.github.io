# Оплата { #payment }

Подключите онлайн-оплату или предложите покупателю оплатить заказ при получении.

Откройте **Настройки → Оплата**.

<span id="_2"></span>

## Создание способа { #creating-a-method }

1. Нажмите **Новый сервис**, выберите провайдера и введите реквизиты из его кабинета. Наименование видно покупателю и должно быть уникальным.
2. При необходимости задайте комиссию и срок ожидания платежа. Комиссия увеличивает стоимость товаров, но не доставки; у Альфа банка её нет. После истечения срока неоплаченный заказ получает **Ошибка оплаты** с задержкой.
3. На вкладке **Поля заказа** настройте видимость и обязательность контактов. Почта обязательна у Т-Банка и СБП (Т-Банк), у Точка Банк — при фискализации, то есть выдаче кассового чека.
4. Нажмите **Сохранить**. Для нового сервиса **Сохранить активным** включает его во всех сетях и выключает другие сервисы того же типа. Для проверки сначала выберите **Сохранить неактивным**, затем включите способ в [нужной сети](stores-and-delivery.md).

!!! warning "Секретные реквизиты"
    Пароли, токены и секретные ключи вводите только в CRM и кабинете провайдера. Не включайте их в скриншоты и обращения в поддержку. Для уведомлений используйте адреса, показанные CRM, без изменений.

**Картой при получении** и **Наличными при получении** можно изменить, но нельзя удалить. Способ, использованный в заказах, также не удаляется.

Онлайн-оплата в Tellem доступна для заказов в рублях. Для другой валюты используйте оплату при получении.

!!! warning "Перевод онлайн"
    Приложение не показывает реквизиты для этого ранее доступного способа. Выключите его в сетях через **Каталог → Магазины → Управление способами оплаты**. Для уже созданного заказа **Новый** согласуйте оплату с покупателем и нажмите [Принять заказ](orders.md).

## Порядок способов { #method-order }

В **Настройки → Оплата** выберите строку и нажмите **Выше** или **Ниже**. На телефоне эти команды находятся в меню **Действия**. Порядок сохраняется сразу и действует во всех сетях магазинов; покупатель видит только включённые в его сети способы.

<span id="_3"></span>

## Проверка { #testing }

**Сгенерировать тестовую ссылку для оплаты** проверяет, принимает ли провайдер реквизиты. Откройте полученную страницу. Тестовая ссылка не связана с заказом и не меняет его статус в CRM.

Возврат в приложение и смену статуса проверьте настоящим заказом на согласованную небольшую сумму. До проверки не включайте способ во всех сетях.

## Особенности провайдеров { #provider-requirements }

Остальные реквизиты перенесите из кабинета выбранного сервиса.

| Сервис | Что учесть |
|---|---|
| Т-Банк, СБП (Т-Банк); Альфа банк, СБП (Альфа банк) | Необязательный префикс номера заказа: латинские буквы |
| Робокасса | Поддерживается хэш-алгоритм MD5 |
| СБП (Аркопэй) | Выберите одноразовую или многоразовую ссылку СБП |
| Сбербанк, СБП (Сбербанк) | Задайте **Тип контрольной суммы уведомлений** и **Ключ проверки уведомлений**, чтобы CRM принимала уведомления банка |
| Бета трансфер | Задайте **Минимальную сумму платежа** по условиям провайдера. Она ограничивает положительный остаток после списания бонусов и не может понизить минимальный порог сервиса в CRM |
| Точка Банк, Точка Банк (СБП) | [Получите токен и выберите реквизиты](#tochka) |

## Уведомления провайдера { #provider-notifications }

Перенесите адреса из CRM в кабинет провайдера:

- **ЮKassa:** **Данные для личного кабинета → URL для уведомлений**; выберите события `payment.succeeded` и `payment.canceled`.
- **Робокасса:** на той же вкладке Result URL с методом POST, Success URL и Fail URL с методом GET.
- **Бета трансфер:** Result, Success и Fail URL находятся в блоке **Дополнительная информация**.
- **Сбербанк:** запросите адрес у команды Tellem и укажите его в кабинете банка. Без настроенных параметров проверки CRM отклоняет уведомления; статус обновится при следующей проверке платежа.

У Т-Банка и АркоПэй адрес передаётся с платежом, у Альфа банка статус проверяется без уведомлений. У ЮKassa проверка статуса продолжается независимо от переключателя **Обновлять состояние платежей через планировщик**.

## Точка Банк и Точка Банк (СБП) { #tochka }

1. В кабинете Точки откройте **Сервисы → Все сервисы → Интеграции и API → JWT-ключи**. Создайте токен (ключ доступа) с правами для нужного продукта:

    | Продукт | Права |
    |---|---|
    | Карта | `ReadCustomerData`, `MakeAcquiringOperation`, `ReadAcquiringData`, `ManageWebhookData` |
    | СБП | `ReadCustomerData`, `ReadSBPData`, `EditSBPData`, `ManageWebhookData` |

2. Вставьте токен в **Токен доступа** без слова `Bearer`. `client_id` и логин конструктора сайтов не подходят.
3. Выберите загруженные реквизиты: для карты — компанию и торговую точку, для СБП — торговую точку и счёт. Если списки пусты, проверьте срок и права токена, тестовый режим и подключение продукта в банке.
4. Для **Публичный JWK для webhook** нажмите **Получить**. Это публичный ключ банка для проверки уведомлений. Скопируйте **URL webhook-уведомления** в интеграцию Точки и выберите событие `acquiringInternetPayment` для карты или `incomingSbpPayment` для СБП.

Для **С фискализацией** сначала подключите услугу в банке. Настройка действует на новые ссылки; почта покупателя становится обязательной. В чек входят товары с комиссией и доставка, списанные бонусы уменьшают сумму.

В **Тестовом режиме** используйте тестовые реквизиты Точки. Перед рабочими платежами выключите режим, замените токен на рабочий и заново выберите реквизиты. Затем выполните [проверку оплаты](#testing).
